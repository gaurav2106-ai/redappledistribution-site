## 2. Limits to know about

- Security headers: GitHub Pages cannot set custom response headers (no CSP, HSTS tuning, X-Frame-Options, Permissions-Policy). GitHub does send HSTS once HTTPS is enforced. What can be done in the HTML: `<meta name="referrer">` and a `<meta http-equiv="Content-Security-Policy">` (no frame-ancestors, no report-uri through meta). Real headers need a proxy in front such as Cloudflare (free plan) or a move to Netlify, Cloudflare Pages or Vercel. Recommendation: not a launch blocker.
- Redirect rules: GitHub Pages has no server-side redirect rules. Only the CNAME-driven www to apex and http to https redirects exist. Any other redirect must be a meta refresh or JavaScript page.
- Deep links without a file return HTTP status 404 (with the fallback page body). Browsers get the right page, but search engines may treat them as errors. This is why every product, brand and category must have a real static file. Elon is generating these.
- Hash routes: the shop already uses path routes (/shop/p/<id>), so the earlier hash-route SEO concern is resolved for the new build. Old `#/` links are converted by `fixUrl()`.

## 4. Fallback behaviour (404.html), verified by running the logic

| Request | Result |
|---|---|
| /shop/p/2 and /shop/p/2/ | /shop/?/p/2, shop restores the clean path, product page renders |
| /shop/brand/Mr.%20Fog/ and /shop/brand/Wick%27d | brand page, encoded names kept |
| /shop/c/vapes?q=a&b=1 | /shop/?/c/vapes&q=a~and~b=1, runtime restores the query |
| /shop/p (no id), /shop/zzz | shop renders its not-found page (noindex) |
| /nope (outside /shop/) | redirects to the landing page (the landing is the only page outside /shop/) |

Loop risk: none, /shop/ always exists. When Elon adds static files, GitHub serves the real file and 404.html is not involved, so the fallback keeps working for any route that has no file. A static page for a product must still load the shop runtime and keep `<base href="/shop/">`.

## 5. Rollback

Fast rollback (about 2 minutes, then Pages rebuild):
1. `git checkout main && git revert -m 1 <merge commit>` then `git push origin main`. [APPROVAL]
2. Or hard reset to the safety tag: `git reset --hard pre-burgundy-launch` then `git push --force-with-lease origin main`. [APPROVAL, force push, only if revert is not enough]
3. Wait up to 10 minutes for browser cache (max-age 600). sw.js does not cache, so no extra clearing is needed.
4. Re-run the live URL checks from step 11.
